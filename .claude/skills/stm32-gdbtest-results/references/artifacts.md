# Карта артефактов и примеры интерпретации

Порядок появления: входы → prepare → аппаратный запуск → capture → cleanup/итог →
явная выборка → export/index → verify → report. Не все файлы существуют в каждом исходе.

| Артефакт | Роль и предел доказательства |
| --- | --- |
| session.toml, api.toml, target.toml, данные проекта | параметры запуска и ожиданий; текущие файлы могли измениться после запуска |
| session.json | генерируемый дескриптор с путями, не итог теста и не замена session.toml |
| ELF, build-manifest.json, manifest образа | происхождение сборки и образ; успешная сборка не подтверждает исполнение |
| ZIP pack | переносимые входы; связь с запуском подтверждает result.package.sha256, не одинаковый ELF |
| contract-request/result.json, contract-preflight.log | проверка ELF до сервера; отсутствие result может быть сбоем GDB/пути, не отсутствием символа |
| result.json | итог одной попытки; первичный источник status, command_code, checks и ошибок |
| records.json | opt-in снимок runtime-журнала; schema/run_id/case_id/records; не существует автоматически |
| junit.xml | представление для CI; сверь ID, failure/error/skipped и причину с JSON; расхождение расследуй |
| gdb.log, server.log | сценарий/агент и сервер/USB; ошибочная строка требует контекста фазы |
| tunnel.log, recovery.log | условные файлы SSH/восстановления; их отсутствие само по себе не дефект |
| selection.json | явный список попыток, метки стендов, дополнительные свидетельства и пакеты |
| index.json | пути относительно --root, хеши и принадлежность; не оценка смысла тестов |
| export.json, records.csv | общий журнал всех выбранных запусков; данные JSON сохраняют типы |
| measurements.csv | только явная проекция export.toml; не каждый record является измерением |
| summary.json | зависит от производителя файла: API040 driver, CI или export; сначала установи схему/источник |
| integrity.json | проверка файлов на момент verify/report, не доказательство автора или состояния платы сейчас |
| campaign.json/html | представление всех попыток, независимых статусов и диагностики; не новый прогон |

## Минимальная выборка

Корень evidence содержит `run-001/`. Не создавай фиктивные файлы для отсутствующих ролей.
Роли result/records резервированы и выбираются автоматически, остальные явно:

```json
{
  "schema": 1,
  "name": "Board checks",
  "runs": [
    {
      "result": "run-001/result.json",
      "stand": "f411-lab",
      "artifacts": {
        "junit": "run-001/junit.xml",
        "scenario": "inputs/test_board.py"
      }
    }
  ]
}
```

Пути — относительные POSIX без .. и symlink. Повторы case ID сохраняются как отдельные попытки;
одинаковый run_id недопустим. Старый отчёт без ID не переписывай: правила assigned_id —
в [RESULTS](../../../docs/ru/RESULTS.md).

## Проверка журнала и статистика

В session.toml `[results] capture = true` включает сохранение. Runtime record/records сами по себе
не означают запись на диск. normal/interrupted/unknown обозначают завершённость захвата, не PASS/FAIL.
Для SKIP обычно saved/interrupted; finally может оставить запись, но тело после skip не выполняется.
Ошибка захвата даёт command_code=2, сохраняя исход сценария.

sequence — порядок внутри одного запуска, не время. Не объединяй серии разных run_id без явного
правила. Значения 0, false, null и missing различны; крупные целые сохраняй как JSON, не float.
Для среднего/СКО выясни единицы, качество измерения, число образцов, выборочную или генеральную
формулу (N−1/N) и пропуски. Не вычисляй физическую частоту по sequence. records с именем
measurement могут быть любыми данными: интерпретация задаётся автором сценария и export.toml.

Integrity ok означает совпадение с baseline; unverified — первый снимок без прежней опоры,
changed — несовпадение, missing — отсутствие. Новый baseline не доказывает неизменность до индексации.

## Три примера вывода

1. **Условный SKIP.** Сценарий читает optional_loop=false, записывает capability и вызывает skip;
   в журнале capability/optional.finally, code77 и JUnit skipped с той же причиной.
   Вывод: отключение сработало; optional.executed отсутствует; работоспособность цикла не проверена.
   Если условие было true, тот же SKIP неожиданен и кампания не принимается.
2. **Измерения.** Проверенный сценарий сделал N различных публикаций ADC, проверил sequence,
   quality и диапазоны, сохранил samples и summary. Вывод ограничен этой серией и конфигурацией;
   без внешней опоры это не доказательство точности ADC. Нет записи — не ноль в среднем.
3. **Контракт до MCU.** contract-preflight.log содержит FileNotFoundError существующего request,
   нет агентского отчёта/проверенного образа. Вывод: подготовка не состоялась; аппаратного FAIL нет.
   На Windows проверь длину пути и [HOWTO](../../../docs/ru/HOWTO.md). Успешный повтор хранится
   отдельно и не удаляет первоначальную ошибку. Не переносить причину длинного пути на любой FileNotFoundError.

Дополнительно: PASS checks вместе с ERROR cleanup отвергает итоговый запуск; успешный HTML
не исправляет ни cleanup, ни повреждённый records. Отказ через ret проверяет реакцию на инъекцию,
а не реальную электрическую неисправность. Предупреждение inferred_stop — ограничение доказательства
причины остановки; оно не становится ни аппаратным FAIL, ни гарантией точного stop event.
