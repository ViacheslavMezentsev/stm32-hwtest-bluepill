# Остаточное состояние, события и внешние свидетели

Используй [TECH-021–026](../../../docs/ru/TESTING_TECHNIQUES.md#tech-021)
и [шпаргалку](../../../docs/ru/SCENARIO_CHECKLIST.md), не копируй прикладную логику потребителя.

## Приёмы и границы переноса

| Приём | Проверка | Ограничение |
| --- | --- | --- |
| Следующая операция | После завершения/ошибки подать другие данные без reset, проверить точные байты и число публикаций | PASS первой операции не доказывает очистку |
| Порядок кольца | wrap, busy, enqueue, complete, повтор complete; неизменность уже начатого сегмента | Выбранный порядок не доказывает все гонки |
| Время автомата | Граница−1, граница, граница+1; переполнение при известном диапазоне | Логический expire не физическое измерение |
| DMA и драйвер | Сверить HAL/RAM и регистры; остановить только принадлежащий тесту поток до изменения буфера | Обратная запись объекта не восстанавливает MMIO/W1C/FIFO |
| Счётчики и стоимость | Модульная разность с доказанным пределом, отдельный overhead контроля | Среднее/максимум выборки не WCET |
| Фильтр и частота | Независимая формула и фактический dt, шум отдельно от ступени/выброса | Дисперсия не точность; нет данных не ноль |
| Внешний захват | Готовность приёмника до live-окна, время/единицы/пропуски, drain и cleanup | Два представления одного поля не независимый эталон |

## Исполняемая основа

[tests/stateful-buffer](../../../tests/stateful-buffer/README.md): один C++-модуль,
POD без указателей, реальные функции, Target.call и снимок по размеру типа ELF.
В finally восстанавливается весь объект и проверяется чтением; FAIL сохраняется.
Для C++ не угадывай sizeof/смещения и не обходи контракт call выражениями со скрытым вызовом.
В async-функции используй await call; обычному сценарию без live-окна достаточно def.

Из корня модуля:

```sh
python tests/stateful-buffer/run.py --host-only
```

Затем команда Renode Windows/Linux из README примера с фактическими путями инструментов.
Матрица: дефект остатка, дефект порядка, исправленный вариант и повтор. В Renode
12 исходов, включая три намеренных FAIL; ожидаемы конкретные проверки, а не любой
ненулевой код. Host дополнительно проверяет полную очередь. Проверь capture,
восстановление и освобождение собственных процессов; summary PASS не меняет FAIL.

Сначала воспроизведи исходный дефект, затем теми же сценариями исправление и соседние
случаи. Подстрой данные/ожидания под требование, а не тест под ошибочный actual.
При переносе на MCU отдельно докажи владение памятью и допустимый контекст, добавь
MMIO/SVD, внешние ресурсы и восстановление. Этот пример не проверяет DMA/IRQ/RTOS.

Для DDTT запиши применимость, исходный результат и вердикт анализа отдельно.
Для отчёта используй [results](../../stm32-gdbtest-results/SKILL.md), затем
[report](../../stm32-gdbtest-report/SKILL.md); рисунок не заменяет проверку данных.

## Время, стоимость и совместный захват

Для этих задач продолжи по [нейтральным маршрутам](neutral-workflows.md): выбор
logical-time/counter-cost/external-capture, команды, отрицательные контроли и границы
выводов. Не трактуй явный expire примера stateful-buffer как измерение времени.
