# MMIO/SVD в HIL

[English](MMIO_SVD.en.md)

Потребитель закреплён на stm32-gdbtest v0.6.0 (API_VERSION=3).
Ядро модуля и прошивка здесь не изменены. Все 28 сценариев остаются обычными def:
синхронная навигация совместима, await для них не требуется.

## Граница описания

Обе сессии hil/F103C8/session.toml и hil/F103CB/session.toml выбирают
../common/stm32f103-test.svd относительно файла сессии. Это собственное **подмножество
для тестов**, 35 регистров, а не полный SVD производителя. Адреса/размеры сверяются
с CMSIS STM32CubeF1 v1.8.7 из текущего ELF; права и эффекты заданы по RM0008 и PM0056.
FACTORY.FLASH_SIZE — имя проекта для 16-битного размера Flash; ширина проверяется
отдельно, поскольку CMSIS задаёт только адрес.

| Область | Использование |
| --- | --- |
| RCC, GPIOA/B/C | Настройки тактирования, KEY, вывод LED |
| SysTick | CTRL и LOAD |
| USART1 | SR, BRR, CR1; данные DR не читаются |
| ADC1 | CR1/CR2, SMPR1, SQR1/SQR3; DR описан с эффектом, сценарии его не читают |
| DMA1 / DMA1_Channel1 | ISR и конфигурация канала; IFCR описан как WO/W1C для отказных проверок |
| DBGMCU, FACTORY | Идентификатор и размер Flash |

Описание не доказывает корректность платы и не моделирует все зависимости регистров.
В USART SR выбран консервативный доступ read-only: сценарии не сбрасывают флаги
записью, хотя аппаратный регистр допускает отдельные записи.

## Доступ и эффекты

- Регистры читаются через t.mmio.read("GPIOB.ODR"). Маски CMSIS вычисляются
  отдельно через evaluate, без разыменования периферии. Сравнения Python выполняются
  отдельными check; таблицы остаются для RAM и обычных выражений.
- SysTick CTRL: allow_effects=True, поскольку чтение сбрасывает COUNTFLAG.
  В HW_SETUP_DONE три бита проверяются по одному снимку CTRL.
- USART SR: явное согласие на эффект начала последовательности SR→DR.
  Сценарий не читает DR; последующий доступ прошивки остаётся за пределами этой гарантии.
- ADC CR2: явное согласие на командные эффекты. В HW_DMA_TIMEOUT чтение и запись
  разделены, записывается заранее вычисленное число. В finally читается текущее CR2
  и возвращается только бит DMA; если число не изменилось, повторной записи нет.
  Это проектная операция в известной остановке, **не универсальный безопасный RMW**.
- MMIO write подтверждает транспортный ответ, не выполняет скрытое чтение до/после
  записи. Неоднозначный ответ не повторяется автоматически. Периферия может продолжать
  работать при остановленном ядре; восстановление и выбор точки — ответственность сценария.
- RAM (g_monitor, g_post), аргументы, локальная копия status в DMA ISR и регистры CPU
  сохраняют read/write/memory/ret. Выражение &ADC1->DR вычисляет адрес, а не читает DR.
  Отказ memory(USART1_DR, 4) оставлен как отрицательная проверка окна памяти.

Экспертное исключение: monitor::process(&g_monitor.raw[0], count) пока вызывается
непосредственно через Python GDB в основном потоке, в синхронном сценарии, с сохранением
и восстановлением RAM. Публичный call() не принимает такой namespace/указатель.
Переносить этот обход в async-сценарий нельзя; MMIO-контракт на него не распространяется.

## Проверка без платы

Из корня проекта, для каждого f103c8-hil и f103cb-hil:

    cmake --preset f103cb-hil
    cmake --build --preset f103cb-hil
    ctest --preset f103cb-hil-host --output-on-failure
    python -m unittest discover -s hil/tools -p "test_*.py"
    python modules/stm32-gdbtest/stm32_gdbtest/cli.py inspect --session build/f103cb-hil/hwtest/session.json

Host-набор: 28 prepare, traceability, MMIO-регрессии и сверка SVD/ELF (31 тест CTest).
host.svd_elf запускает GDB только с ELF, без target remote.
В Linux те же команды; ARM_TOOLCHAIN_ROOT указывает на Linux-toolchain.
CI повторяет host-проверки и стиль сценариев. pack захватывает SVD вместе с конфигурацией;
он не требует исходного SVD на машине запуска. POST/DMA сценариям с поиском строк
по-прежнему нужны исходники проекта, поэтому это маршрут checkout, не обещание
автономного запуска всех сценариев из ZIP.

Имена сценариев и проверок DDTT сохранены. Старые аппаратные результаты не являются
приёмкой новых сценариев: перед новым экспортом нужна свежая кампания на согласованной
плате и ревизии. Офлайн PASS не подтверждает GPIO/DMA на физическом STM32.

Описание SVD включено во входы кампании DDTT: его изменение после кампании блокирует
переносимый экспорт, даже если прошивка и имена проверок остались прежними.
