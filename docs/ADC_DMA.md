# ADC/DMA и обработка отсчётов

[English](ADC_DMA.en.md) · [Начальный DDTT](DDTT_STARTUP.md)

Монитор работает после штатного POST из `loop()`. ADC1 сканирует VREFINT (17) и температуру (16),
DMA1 Channel1 переносит восемь пар halfword в принадлежащий `g_monitor` буфер. Режим normal,
без кольца: после TC обработчик выключает ADC и DMA, затем публикует ready. Основной цикл
обрабатывает только неподвижный блок. Новый запуск — не чаще чем раз в 100 мс; стабилизация
внутреннего датчика занимает 2 мс. Таймаут >10 мс освобождает канал; следующий блок повторяется.
TE учитывается отдельно. В этой серии реальный TE не инжектировался и его ветвь не раскрашена.

POST сохраняется; монитор использует выполненную POST калибровку. Его собственная повторная
калибровка не добавлена. LED продолжает прежнее мигание, `g_monitor.normal` пока не управляет им.

Обработка находится в [monitor_processing.cpp](../src/monitor_processing.cpp), без CMSIS:
среднее восьми пар, VDDA по типовым 1200 мВ и температура по 1430 мВ при 25°C и 4.3 мВ/°C.
Два независимых скалярных фильтра имеют одинаковую формулу Q=1,R=4,Pinitial=1; это демонстрационная
настройка, не подбор шумовой модели датчиков. Первый отсчёт задаёт значение без смешивания с нулём.
Неверная длина/указатель, нулевой VREFINT или код >4095 отклоняют весь блок до обновления фильтра.
VDDA 2900..3600 мВ и T -10..85°C задают `normal`. Точность датчика не калибруется этим тестом.

## Свидетельства 15.10.2026

WeAct BluePill-Plus F103CB_PB2, OpenOCD 0.12.0/ST-Link, xPack 14.2.1-1.1/GDB 15.2.90.
Полная аппаратная серия — 18/18 PASS, команды 0, capture SAVED. Host/prepare C8 и CB — 19/19.
C8 проверен сборкой и подготовкой, не на плате. Renode CB smoke PASS подтверждает запуск и мигание,
но не моделирование DMA. Release CB собран. Новый код отформатирован clang-format 23.1.3 по
предоставленным правилам; пользовательская `.clang-format` не включена в коммит.

| Проверка | Результат и граница |
| --- | --- |
| HW_DMA_CAPTURE | Регистры scan/DMA, реальный TC IRQ, CNDTR=0, три блока и три публикации. ADC/DMA отключены до чтения CPU. В примере VREFINT 1492..1494, T 1771..1774. |
| HW_DMA_PROCESS | Векторы 1500/1800 → 3276 мВ, 22.6744°C; второй 1560/1800 → 3150 мВ, после фильтра 3234 мВ. Неверные блоки не меняют фильтр; весь MonitorState восстановлен. |
| HW_DMA_TIMEOUT | Отключение ADC DMA request даёт один таймаут, не публикует результат, следующий блок принимается. Это модель отсутствия запросов, а не физический дефект DMA. |
| Host C++ | Та же функция на host: первый/второй отсчёты, null, неверная длина, нулевой хвост, код >4095 и неизменность фильтра. |
| Негативный контроль | Локальная копия сценария с заведомо неверными 9999 мВ дала FAIL; finally восстановил снимок. Не выдаётся за исходный дефект новой функции. |

Первая попытка HW_DMA_PROCESS дала ERROR: `Target.call()` не принимает namespace. Память
восстановлена. Исправлен сценарий, не прошивка: `gdb.parse_and_eval("monitor::process(...)")`
в основном потоке GDB; bool-результат явно сохранён в `processing.call`. Это прямой GDB,
а не обещание поддержки C++-имён методом call. Прямой вызов не попадает в mutations как call;
его свидетельство — records и последующие проверки. Никаких тестовых обёрток в прошивке нет.

## Где теперь подробности раскраски

Карта содержит 54 подтверждённые связи на 49 строках. Непроверенные ветви не закрашиваем.
После обычных bind_map.py и ddtt_coverage.py из [инструкции](DDTT_STARTUP.md) выполните:

```powershell
python hil/tools/ddtt_report.py --runs "$campaign/runs" --view build/ddtt-view
```

В VS Code: **Coverage Gutters: Watch** для полосок; **Coverage Gutters: Preview Report** для
`build/ddtt-view/index.html`. HTML также открывается обычным браузером. Встроенный preview может
ограничивать ссылки на локальные файлы и внешний протокол VS Code.

Отчёт показывает:
- исходник/строку и точное утверждение;
- ссылку на определение сценария через `vscode://file`;
- выбранную попытку, дату/возраст на момент генерации, факт/ожидание (в том числе повторные проверки);
- ссылки на result.json и records.json;
- число аппаратных попыток **в выбранной кампании**, число с тем же ELF и раскрываемую историю;
- поиск и фильтр CONFIRMED/FAILED/UNKNOWN, автоматическую светлую/тёмную тему.

Это не общее число запусков за всю историю. Совпадение ELF не означает успешную попытку.
Выбор свидетельства и его валидность по-прежнему определяет экспортёр, отчёт дополнительно
проверяет SHA результата. При подмене не остаётся старой зелёной HTML-страницы. DA остаётся
булевым исходом, не количеством попыток. Coverage Gutters сам эти связи из LCOV не извлекает.
Ссылки/HTML-экранирование и отказ при изменённом result проверяются host-тестом.

## Повторить проверки

```powershell
python hil/tools/check_monitor.py
python -m unittest discover -s hil/tools -p test_ddtt_report.py
cmake --preset f103cb-hil
cmake --build --preset f103cb-hil
ctest --preset f103cb-hil-host
ctest --preset f103cb-hil-hw
```

Для изолированной кампании и карты используйте маршрут DDTT_STARTUP. Не подмешивайте архивные
попытки от другого ELF. Host-компилятор g++ нужен только для численных векторов; MCU использует Arm GCC.
Следующие возможности: связь индикации с normal, кнопка, дополнительные отказные ветви. В этом
пакете их подтверждение не заявляется.
