# Индикация измерений и просмотр DDTT

[English](MEASUREMENT_LED.en.md) · [ADC/DMA](ADC_DMA.md)

| Состояние | PB2 на WeAct | Основание |
| --- | --- | --- |
| MeasurementPending | Выключен | Ещё нет результата текущего мониторинга |
| MeasurementNormal | Мигание, полупериод 500 мс | Фильтрованные VDDA 2900..3600 мВ и T −10..85°C |
| MeasurementFault | Постоянно включён | Неверный блок, выход из диапазона, timeout или DMA TE |

`g_monitor.state` — последнее состояние, `g_app.indication` — показанное в loop.
Ошибки не стирают фильтры; следующий валидный блок снова определяет состояние. Поэтому после
выхода за диапазон восстановление может занять несколько блоков. Счётчики ошибок остаются
историей, не вечным запретом нормы. После восстановления переключение LED возобновляется по
прежнему времени `last_toggle_ms`, а не с новой фазой. Изменение состояния отображается в
следующем loop. Это учебная индикация, не независимая защита от зависания MCU.

## Проверка на WeAct, 15.10.2026

План: [measurement-led](../hil/common/plans/measurement-led.md). Исходный сценарий
HW_INDICATOR_INVALID дал FAIL `fault lights LED`: после нормального блока и нулевого VREFINT
LED был выключен. Буфер восстановлен, finally выполнил чистый startup. После изменения та же
проверка PASS; промежуточная неудачная сборка/попытка также сохранена локально.

- HW_INDICATOR_NORMAL: выключен после первого loop, затем мигание при реальных измерениях.
- HW_INDICATOR_INVALID: нулевой VREFINT после нормы, постоянный LED, отмена прежней нормы,
  следующий нормальный блок и возобновление мигания.
- HW_INDICATOR_RANGE: VREFINT=3000 (1638 мВ до фильтра), отказ после фильтрации,
  восстановление штатными блоками в пределах десяти попыток без сброса фильтра.
- HW_DMA_TIMEOUT: отсутствие ADC DMA requests даёт таймаут и включённый LED;
  следующий блок принимается.

Инъекции делаются только в неподвижном блоке после отключения DMA; память проверяется обратным
чтением и возвращается до следующего запуска. Сброс в finally снимает последствия в фильтрах.
Полный набор: **21/21 HW PASS**, capture SAVED; подготовка C8 и CB: **22/22 PASS**.
Native C++ проверяет отмену нормы и возврат после invalidate. CB release собран, Renode 1.17
подтвердил запуск и отказную индикацию: ADC/DMA в модели отсутствуют. C8 аппаратно не проверен.
Реальный DMA TE не инжектирован и не раскрашен. Проверка ODR не является оптическим измерением.
Остановки GDB не подтверждают временные гарантии свободного исполнения.

Карта: **64 связи / 55 строк**, все подтверждены свежей полной аппаратной серией.
Карта связывает утверждения с кодом по решению сценариста, а не измеряет построчное исполнение.
Порядок экспорта — [DDTT_STARTUP](DDTT_STARTUP.md), генератор подробностей:

```powershell
python hil/tools/ddtt_report.py --runs "$campaign/runs" --view build/ddtt-view
```

## Тема отчёта

HTML оформлен в стиле GitHub. По умолчанию тёмный. Круглая кнопка справа от фильтров:
**☾ тёмная → ☀ светлая → ◐ авто**. Выбор сохраняется в localStorage, если окно разрешает
хранение; при его блокировке кнопка работает до перезагрузки. Авто учитывает классы темы
VS Code, если preview передаёт их в документ, иначе системную цветовую схему. Отдельный iframe
может не знать тему редактора — в этом случае выберите тёмную вручную. Никаких внешних CSS/JS/CDN.
После обновления HTML закройте и снова откройте Preview Report либо обновите браузер.

Ссылки, SHA свидетельств и тема проверены host-тестами; цикл кнопки, сохранение выбора,
приоритет темы VS Code и блокировка storage — исполнением JS через Node.js.
Внешний вид внутри конкретного VS Code preview требует проверки пользователем.
