# Кнопка WeAct и актуальность раскраски DDTT

[English](BUTTON.en.md) · [Окружение](DEVELOPER_ENVIRONMENT.md)

## Поведение

В WeAct BluePill-Plus V1.1 KEY (SW2) подключена через R4 330 Ом к PA0 и при
нажатии подаёт 3,3 В: активный уровень высокий. Внешней подтяжки вниз нет;
прошивка включает внутреннюю pull-down. Основание — [официальная схема](https://github.com/WeActStudio/BluePill-Plus/blob/master/HDK/BluePillPlus_V11_SchDoc.pdf).
Ранние измерения плавающего входа не подтверждали полярность.

После 30 мс устойчивого нажатия LED PB2 горит постоянно, независимо от состояния
измерений. Удержание не повторяет событие и не позволяет миганию погасить LED.
После 30 мс устойчивого отпускания возвращается индикация измерений:
ожидание — выключен, норма — мигает, отказ — постоянно включён.
Профиль F103C8 не объявляет пользовательскую KEY; два сценария кнопки завершаются SKIP.

Для ручной проверки поставьте breakpoint на `++presses` в [button.cpp](../src/button.cpp):
он срабатывает один раз после подтверждённого нажатия. Для состояния смотрите
`g_button.candidate`, `stable`, `changed_ms`, `presses`. Остановка GDB влияет на время;
это не измерение реального дребезга контактов.

## Как обновлять раскраску

После изменения исходников нужны пересборка и свежая аппаратная кампания.
Затем выполните VS Code → Run Task → **HIL: DDTT report (F103CB)** и укажите
каталог `runs` нужной кампании. Эквивалент из корня проекта:

```powershell
python hil/tools/ddtt_export.py --runs build/<campaign>/runs
```

Команда перепривязывает карту, экспортирует LCOV и создаёт HTML. Перед генерацией
старая раскраска очищается. Комментарии `//`, `/* ... */` и пустые строки отвергаются;
код с комментарием справа допустим. Проверяются однозначность якоря и соответствие
строки, а при чтении свидетельства — SHA-256 исходника. Одна проверка комментария
не выявила бы сдвиг на другую строку кода, поэтому нужны обе проверки.
Это простая лексическая проверка, не разбор исполнимости C++.

Отчёт: `build/ddtt-view/index.html`; раскраска: `build/ddtt-view/lcov.info`.
Проверки запускаются при экспорте, а не при каждом редактировании в IDE. После правок
снимите старые отметки командой Coverage Gutters: Remove Coverage; после нового экспорта
включите Watch/Display Coverage. Старые журналы сохраняйте, но не выдавайте их за новый прогон.
Не используйте прямой вызов экспортёра подмодуля вместо этого маршрута: дополнительные
проверки комментариев находятся в инструментах данного проекта.
